Etha3a API is public, open-source, and designed for straightforward
integration. You do not need an account or API key to try it.

<Info>
  Base URL: `https://api.bonyanoss.org/etha3a/v1`
</Info>

<Steps>
  <Step title="Pick a base URL">
    - **Hosted:** `https://api.bonyanoss.org/etha3a/v1`
    - **Self-hosted:** `http://localhost:3000` when running your own API instance.
  </Step>
  <Step title="Make a request">
    <CodeGroup>
    ```bash cURL
    curl https://api.bonyanoss.org/etha3a/v1/ayat/1
    ```

    ```js JavaScript (fetch)
    const res = await fetch("https://api.bonyanoss.org/etha3a/v1/ayat/1");
    const json = await res.json();
    console.log(json.data.aya.text);
    ```

    ```ts Node.js (axios)
    import axios from "axios";

    const { data } = await axios.get("https://api.bonyanoss.org/etha3a/v1/ayat/1");
    console.log(data.data.aya.text);
    ```

    ```py Python (requests)
    import requests

    r = requests.get("https://api.bonyanoss.org/etha3a/v1/ayat/1")
    print(r.json()["data"]["aya"]["text"])
    ```

    ```php PHP
    <?php
    $json = file_get_contents("https://api.bonyanoss.org/etha3a/v1/ayat/1");
    $data = json_decode($json, true);
    echo $data["data"]["aya"]["text"];
    ```

    ```go Go
    package main

    import (
        "encoding/json"
        "fmt"
        "net/http"
    )

    type Resp struct {
        Success bool `json:"success"`
        Data    struct {
            SurahNumber int    `json:"surahNumber"`
            SurahName   string `json:"surahName"`
            Aya         struct {
                Number        int    `json:"number"`
                Text          string `json:"text"`
                NumberInSurah int    `json:"numberInSurah"`
            } `json:"aya"`
        } `json:"data"`
    }

    func main() {
        r, _ := http.Get("https://api.bonyanoss.org/etha3a/v1/ayat/1")
        defer r.Body.Close()
        var out Resp
        json.NewDecoder(r.Body).Decode(&out)
        fmt.Println(out.Data.Aya.Text)
    }
    ```
    </CodeGroup>
  </Step>
  <Step title="Read the envelope">
    Most module endpoints follow one of two shapes:

    ```json Success
    { "success": true, "data": { "surahNumber": 1, "surahName": "الفاتحة", "aya": { "number": 1, "text": "...", "numberInSurah": 1 } } }
    ```

    ```json Failure
    { "success": false, "message": "human-readable error" }
    ```

    Your client can keep one error path instead of handling many upstream API
    formats. See [Errors](/concepts/errors) for the status-code matrix.
  </Step>
</Steps>
