---
title: "Validated provider fallback"
description: "Source order and the contracts preserved on failover."
---

Sources run sequentially on a cache miss. The adapters validate coverage, identity and required fields before accepting data; empty or malformed results cause the next source to be tried. Exhausted sources return 503. SDK retries repeat the API request and are separate from this server behavior.

| Module | Source order |
| --- | --- |
| Surah | mp3quran.net, alquran.cloud, quran.com, local canonical metadata. |
| Ayat | alquran.cloud, pinned fawazahmed0 dataset through jsDelivr, quran.com. |
| Reciter catalogue | mp3quran.net, bundled local snapshot preserving IDs and recordings. |
| Reciter audio | Verified mp3quran URL, then matching Quran.com recording where mapped. |
| Tafsir | muyassar: alquran.cloud, quranenc.com, quran.com, pinned spa5k mirror. saadi: quran.com, pinned spa5k mirror. |
| Azkar | Pinned rn0x/hisn_almuslim_json dataset through jsDelivr, then raw GitHub. |
| Hadith | Local book catalogue; content from pinned gadingnst dataset through jsDelivr, then raw GitHub. |
| Prayer | Aladhan, then local adhan for coordinates. City-only requests have no local fallback. |
| Hijri | Aladhan UAQ validated against local islamic-umalqura conversion, then local Intl. |
| Qibla | Aladhan, then local bearing calculation. |

Read apiName for provenance. Canonical surah names, reciter identities, public tafsir IDs, prayer date/method/timezone and the Umm al-Qura calendar are preserved across supported fallbacks. Optional fields remain optional: the current azkar corpus supplies text without repetition counts or references; local prayer results may omit hijri.

The shared fetch timeout defaults to 8 seconds, with overrides up to 30 seconds for hadith books. Sequential fallbacks and paginated provider reads can exceed the SDK default 10-second attempt timeout. Choose a timeout appropriate to cold loads and use cancellation for a total deadline.
