---
title: "Play a selected recording"
description: "Choose a moshaf with the required surah and narration."
---

The reciter catalogue preserves mp3quran IDs in its local fallback. Every reciter has normalized moshaf recordings containing surahList, rewayaId and type. Select a recording that covers the surah and matches your desired narration.

```ts
import { BonyanClient } from '@bonyanoss/bonyan-api';

const client = new BonyanClient({ timeoutMs: 45000, retry: 1 });
const surah = 1;
const reciters = await client.reciters.list();
const reciter = reciters.find(item => item.moshaf.some(m => m.surahList.includes(surah)));
if (!reciter) throw new Error('No recording covers this surah');
const recording = reciter.moshaf.find(m => m.surahList.includes(surah))!;
const result = await client.reciters.getSurah(reciter.id, surah, { moshaf: recording.id });
console.log(result.audio, result.moshafId, result.rewayaId, result.apiName);
```

Without moshaf, the API prefers Hafs murattal covering the surah, then another covering recording. It verifies URLs with HEAD and rejects unavailable audio. Quran.com fallback is restricted to verified recordings of the same reciter, narration and style.

No matching recording returns 404. Failure of all eligible audio sources returns 503. A successful check is cached for 15 minutes; playback can still fail later. Set the returned audio URL on an HTML audio element, show controls and handle its error event. The API returns JSON; the browser loads audio from the provider.
