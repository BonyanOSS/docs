---
title: "Self-host the API"
description: "Run with Node.js, Docker or native Cloudflare Workers."
---

The API server requires Node.js 24 (`>=24 <25`) and pnpm 10.33.4. The SDK and docs use their own package settings. The server needs no database or provider API key, and needs outbound HTTPS for external content.

## Local server

```bash
git clone https://github.com/BonyanOSS/Bonyan-API.git
cd Bonyan-API
corepack enable
corepack prepare pnpm@10.33.4 --activate
pnpm install --frozen-lockfile
pnpm dev
```

Copy .env.example to .env before starting using cp on Unix or Copy-Item in PowerShell. The local URL is http://localhost:3000 without a version prefix. PORT/HOST configure the listener; RATE_LIMIT_MAX/RATE_LIMIT_WINDOW configure the budget; CORS_ORIGIN lists allowed origins; TRUST_PROXY controls proxy trust; LOG_LEVEL controls logging; CACHE_MAX_ENTRIES controls cache capacity. Only literal true enables TRUST_PROXY; use it behind a trusted proxy.

```bash
pnpm lint:check
pnpm test
pnpm build
pnpm start
```

## Docker

The Dockerfile uses Node 24 Alpine and starts dist/server.js. To test it:

```bash
docker build -t bonyan-api .
docker run --rm -p 3000:3000 --env-file .env bonyan-api
```

## Cloudflare Workers

Deployment uses src/worker.ts with a native Fetch adapter and nodejs_compat, without a container. wrangler.toml sets compatibility date 2026-10-04 and custom domain api.bonyanoss.org, with preview_urls=true and workers_dev=false. Worker environment values come through bindings; PORT and HOST do not create a listener there.

```bash
pnpm cloudflare:check
pnpm cloudflare:startup
pnpm deploy:cloudflare
```

The first command checks the bundle without deploying; the second checks Worker startup through /health, /ready and /tafsir. Deploy requires a configured Cloudflare account/domain. The v2 migration removes the old container class; preserve the migration history for existing deployments.

Health and readiness do not contact providers. Include a content request when checking availability and read /metrics as text. Cache and limits belong to each process or Worker isolate. See [operations](/locales/en/guides/operations).
